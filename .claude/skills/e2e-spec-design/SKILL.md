# E2Eテスト仕様書作成

## Required References

このスキルを読み込んだ後、以下のファイルをReadツールで読み込むこと。

**必須**（常に読み込む）:
- `references/quality-checklist.md` - 品質チェック8項目の詳細と修正指示例
- `references/validation-coverage-format.md` - バリデーションカバレッジ表のフォーマット

---

## Overview

画面仕様書からE2Eテスト仕様書を6ステップで生成するワークフロー。

**出力先**: `tests/e2e/specs/{category}/{screen}.spec.md`

---

## ワークフロー

### [1/6] 入力ファイル解析

1. 引数 `$1` から仕様書パスを取得（空の場合はユーザーに質問）
2. Readツールで仕様書を読み込み、以下を特定:
   - **画面情報**: 画面ID、画面名、URL、認証要否
   - **画面要素**: フォーム要素、表示要素、ナビゲーション要素
   - **機能一覧**: 主要機能、副次機能
3. 複数画面が含まれる場合、対象画面をユーザーに確認

### [2/6] 既存テスト分析

重複テスト作成を防止するため、既存テストを調査する。

1. `tests/e2e/specs/**/*.spec.md` と `tests/e2e/tests/**/*.spec.ts` をGlobで検索
2. 以下をチェック:
   - **完全重複**: 同一画面・同一機能のテスト仕様書が既に存在しないか
   - **部分重複**: 類似テストケース（同じ操作手順）が既に存在しないか
   - **関連テスト**: 依存関係のあるテスト（ログイン→ダッシュボード等）が存在するか
3. 分析結果をユーザーに報告し、続行/確認/キャンセルを選択

### [3/6] テストケース設計

1. `Skill('playwright-guidelines')` を参照（テスト仕様書フォーマット、Page Objectパターン、セレクタ戦略）
2. 各画面に対して以下のテストケースを設計:

| 分類 | 内容 |
|------|------|
| **正常系** | 基本フロー、代替フロー、オプショナルフロー |
| **異常系** | バリデーションエラー、認証エラー、サーバーエラー |
| **境界値** | 空入力、最大長、特殊文字 |

3. **バリデーションルール100%網羅（必須）**: 仕様書のすべてのバリデーションルールに対応するテストケースを作成。詳細は `references/validation-coverage-format.md` を参照
4. 優先度を設定（高: クリティカルパス、中: エラーハンドリング、低: エッジケース）
5. テストケース構成をユーザーに確認（承認/高優先度のみ/却下）

### [4/6] テスト仕様書生成

`Skill('playwright-guidelines')` のテスト仕様書フォーマットに従って作成:

- 画面概要（画面ID、画面名、URL、認証）
- 前提条件
- テストケーステーブル（テストID、テスト名、前提条件、操作手順、期待結果、優先度）
- データ要件（テストデータ、Laravelファクトリー）
- Page Object要件
- **トレーサビリティマトリクス（必須）**

**テストID命名規則**: `{CATEGORY}_{SCREEN}_{連番}` または `{CATEGORY}_{SCREEN}_{種別}_{連番}`

#### トレーサビリティマトリクス

全画面要素とテストケースの紐付けを記録する。機能種別ごとの必須カバレッジ:

| 機能種別 | 必須テスト |
|---------|----------|
| **入力** | 正常系✓ 異常系✓ 境界値✓ |
| **表示** | 正常系✓、条件分岐がある場合は異常系✓ |
| **ナビゲーション** | 遷移先確認テスト✓ |

未テスト要素は [5/6] 品質チェックで報告する。

### [5/6] 品質チェック

品質チェック8項目を検証する。詳細は `references/quality-checklist.md` を参照。

**品質ゲート**: 「バリデーション100%網羅」は必須。100%未満の場合は不足テストケースを追加するまで次に進めない。

**品質スコア**: `(合格項目数 / 8) × 100`

| スコア | 判定 | アクション |
|--------|------|----------|
| 100% | 合格 | 次のステップへ進む |
| 70-99% | 条件付き合格 | 警告を表示し、修正を推奨 |
| 0-69% | 不合格 | 修正必須、再チェックが必要 |

品質チェック結果をユーザーに報告し、承認/修正/却下を選択。修正選択時は不合格項目を修正後、再チェック。

### [6/6] 完了と次ステップ

サマリーを表示し、次のアクションをユーザーに確認:
- **テストコード生成**: `Skill('e2e-spec-impl')` でPlaywrightテストを生成
- **レビュー指摘を反映**: テスト仕様書を修正
- **完了**: テスト仕様書作成のみで終了
