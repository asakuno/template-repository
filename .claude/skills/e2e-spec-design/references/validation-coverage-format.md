# バリデーションカバレッジフォーマット

## バリデーションルールの抽出手順

1. **仕様書からバリデーション一覧を抽出**
   - 「バリデーション」「エラーメッセージ」等のセクションを確認
   - 各入力項目のバリデーション条件をリスト化

2. **バリデーション種別ごとにテストケースを作成**

| バリデーション種別 | テストケースの作成基準 |
|------------------|---------------------|
| **必須チェック** | 未入力/未選択時のエラー表示テスト |
| **文字数チェック** | 最大文字数+1の入力でエラー表示テスト + 最大文字数での正常テスト（境界値） |
| **形式チェック** | 不正形式の入力でエラー表示テスト（例: メールアドレス、電話番号） |
| **範囲チェック** | 範囲外の値（下限-1、上限+1）でエラー表示テスト + 境界値での正常テスト |
| **相関チェック** | 項目間の整合性エラーテスト（例: 開始日 > 終了日） |
| **ファイルチェック** | ファイル形式、サイズ、画像サイズ等のエラーテスト |

3. **カバレッジ確認表を作成**

テスト仕様書に以下の形式でバリデーションカバレッジ表を含めること:

```markdown
## バリデーションカバレッジ

| No. | 項目名 | バリデーション種別 | テストケースID | カバー状況 |
|-----|--------|------------------|--------------|----------|
| 1 | メールアドレス | 必須チェック | AUTH_ERR_001 | ✓ |
| 1 | メールアドレス | 形式チェック | AUTH_ERR_002 | ✓ |
| 2 | パスワード | 必須チェック | AUTH_ERR_003 | ✓ |
| 2 | パスワード | 文字数チェック（8文字以上） | AUTH_ERR_004 | ✓ |

**カバレッジ率: X/Y件 (100%)**
```

## 品質ゲート

**バリデーションカバレッジ100%未満の場合、品質チェックで不合格とする。**

不足しているテストケースを自動的に追加提案し、ユーザーに確認を求める。
