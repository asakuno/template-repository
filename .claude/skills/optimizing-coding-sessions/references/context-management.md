## コンテキスト管理

### 基本戦略

コンテキストウィンドウはClaude Codeの最重要リソース。パフォーマンスはコンテキストが埋まるにつれ低下する。

### `/clear` の使用タイミング

- 無関係なタスク間で必ず実行する
- 2回以上修正しても解決しない場合、改善したプロンプトで再開する
- 長いデバッグセッション後にリセットする

### `/compact` の活用

- `compact <指示>` で要約対象を制御する
- 例: `/compact API変更の完全なリストと修正したファイルを保持して`
- CLAUDE.mdに圧縮時の保持ルールを記載できる

### サブエージェントによる調査

調査タスクはサブエージェントに委譲してメインコンテキストを保護する：

```
サブエージェントを使って認証システムのトークンリフレッシュ処理と
既存のOAuthユーティリティを調査して。
```

実装後の検証にも使える：

```
サブエージェントでこのコードのエッジケースをレビューして
```

## セッション運用

### コース修正

- `Esc` - 実行中に即座に停止（コンテキストは保持）
- `Esc + Esc` または `/rewind` - チェックポイントに戻る
- `"それを元に戻して"` - Claudeに変更を取り消させる

### チェックポイント

Claudeのすべてのアクションでチェックポイントが作成される：
- 会話のみ復元（コード変更は保持）
- コードのみ復元（会話は保持）
- 両方を復元

### セッション再開

```bash
claude --continue    # 最新の会話を再開
claude --resume      # 最近の会話から選択
```

`/rename` でセッションに名前を付けて後で見つけやすくする。

## CLAUDE.md最適化

### 含めるべき内容

- Claudeが推測できないBashコマンド
- デフォルトと異なるコードスタイルルール
- テスト手順と推奨テストランナー
- リポジトリの慣習（ブランチ命名、PR規約）
- プロジェクト固有のアーキテクチャ決定
- 環境の特殊事情（必須の環境変数）
- 非自明な落とし穴

### 含めるべきでない内容

- Claudeがコードを読めばわかること
- 言語の標準的な慣習
- 詳細なAPIドキュメント（リンクで代替）
- 頻繁に変更される情報
- 長い説明やチュートリアル
- ファイルごとのコードベース説明
- 「きれいなコードを書く」のような自明な指示

### メンテナンス

- 各行を「削除してもClaudeが間違えるか？」で評価する
- Claudeが指示を無視する場合、ファイルが長すぎる可能性がある
- 重要なルールには強調を追加する（`IMPORTANT`、`YOU MUST`）
- gitにチェックインしてチームで共有する
- skillsやhooksへの分離を検討する

## スケーリング戦略

### ヘッドレスモード

```bash
claude -p "説明" --output-format json     # 構造化出力
claude -p "分析" --output-format stream-json  # ストリーミング
```

### 並列セッション

Writer/Reviewerパターン：
- セッションA: 実装を担当
- セッションB: セッションAの成果物をレビュー

### ファンアウト

```bash
for file in $(cat files.txt); do
  claude -p "Migrate $file from X to Y. Return OK or FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done
```

最初の2-3ファイルでプロンプトを調整してから全体に適用する。
