# 入力成果物とリスクベース選定（E2E設計の上流）

E2Eテスト仕様の設計は「画面仕様書1枚」だけでは不十分。**どの設計成果物を入力にし、どのリスクを優先するか**を最初に固める。

## 1. 必要な入力成果物

| 成果物 | そこから得るもの | 主に支える設計 |
|--------|------------------|----------------|
| **画面仕様書** | 画面要素・機能・バリデーションルール | 責務分類、バリデーション全層割当 |
| **画面遷移図** | 画面（状態）と遷移（操作/イベント） | 状態遷移テスト、画面横断シナリオ |
| **アクティビティ図** | 各操作の前提条件・分岐・事後条件 | シナリオ導出、分岐の網羅 |
| 業務一覧 / ユースケース（あれば） | 業務上のクリティカル度 | リスク選定、ユースケーステスト |
| リスク情報（あれば） | 機能不動作時の影響 | リスクベース選定 |

> 画面遷移図 × アクティビティ図からの**シナリオ導出手順**は、`playwright-guidelines` の `references/scenario-derivation.md` を参照。

## 2. 入力が欠けている場合の扱い

- **画面遷移図 / アクティビティ図が無い**: E2E設計の品質が大きく下がる（状態遷移や画面横断フローが「画面仕様書からの推測」になる）。**強く推奨**として作成・提供を促す。それでも提供されない場合は、画面仕様書から推測で補ったうえで、**推測である旨と限界を仕様書の前提条件に明記**する。
- **業務一覧 / リスク情報が無い**: ステークホルダと重篤度・発生頻度を担当者と簡易に見積もり、根拠を記録する（後述のリスク表）。

## 3. リスクベース選定（機能不動作起点）

「**どの機能が動かないと、誰がどう困るか**」から優先度を導く。リグレッションは新規欠陥の発見より**既存ふるまいの維持確認**が主目的である点を踏まえる。

1. **機能不動作リスクの抽出**: 「この機能が動作しないと何が起きるか」を機能単位で洗い出す
2. **影響の評価（ステークホルダ別）**: 不動作時に誰に（利用者／運用者／経営／その他）どの影響が及ぶか
3. **重篤度 × 発生頻度で優先度付け**（下記の定義）
4. **優先度 → テストレベル / サイズへ割当**（[5. 責務分類とTest size](#5-責務分類レベルとtest-size依存境界の併用)）

> リスクベース選定の戦略的背景は `test-methodology-reviewer` の `references/coverage-strategies.md`（リスクベーステスト／維持・降格基準）を参照。

## 4. リスクレベルの定義

定量化は困難だが、「考慮していなかった」を避けるため複数軸で決める。

| 軸 | 観点 | 段階 |
|----|------|------|
| **重篤度** | 直接的影響・関連機能への波及・短期/長期の金銭影響から、**最も深刻なもの**を基準 | S / A / B |
| **発生頻度** | 対象機能の利用頻度 × 障害の発生しやすさ | High / Medium / Low |

### リスク表フォーマット

| リスクID | 対象機能 | 不動作時の影響（ステークホルダ別） | 重篤度 | 発生頻度 | 優先度 | 割当（レベル / Test size） |
|----------|----------|-----------------------------------|:------:|:--------:|:------:|----------------------------|
| R-001 | … | 利用者: … / 運用者: … | A | High | 高 | E2E / Large |

優先度の高いものを E2E（代表シナリオ）へ、ロジック分岐は下位レベルへ割り当てる。

## 5. 責務分類（レベル）とTest size（依存境界）の併用

2つは別の軸であり、併用する。

- **責務分類（E2E / Feature / Unit）= テストレベル**: どの粒度で検証するか。
- **Test size（Small / Medium / Large）= 依存境界**: Network / DB / 外部システム / threads / sleep などの依存の大きさ。

判断の指針:

- **E2E に残すのは「Large 相当の代表シナリオ・統合境界・Happy path・重大リスク」に限定**。
- **入力条件の組み合わせ・分岐ロジックは下位レベル（Small / Medium）へ**（同値分割・境界値・[原因結果グラフ→デシジョンテーブル](technique-patterns.md)）。
- 「リグレッション＝E2E」と短絡しない（リグレッションは目的、E2E はレベルの1つ）。

> Test size の定義・worked example（同一機能を S/M/L で切り分ける例）は `test-methodology-reviewer` の `references/coverage-strategies.md` を参照。
