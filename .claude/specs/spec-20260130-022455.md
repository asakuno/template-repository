# 実装仕様書: ログイン機能（バックエンド）

## 目的

Laravel 7層アーキテクチャに基づき、セッションベースのログイン・ログアウト認証APIを実装する。既存のフロントエンドUI（LoginForm, PasswordInput, Login page）と接続可能なバックエンドを構築する。

## 要件

- [ ] メールアドレス・パスワードによるセッション認証（Laravel Sanctum SPA認証）
- [ ] ログイン成功時のセッション再生成（セキュリティ）
- [ ] ログアウト時のセッション無効化・トークン再生成
- [ ] ログイン試行のレート制限（5回/分、メール+IPベース）
- [ ] 認証済みユーザー情報取得API
- [ ] バリデーション（email: required|email, password: required|min:8）
- [ ] PHPUnit Feature/Unit テスト（UseCase 80%+, Controller 70%+）
- [ ] API仕様書・セットアップガイド

## 技術仕様

- 言語: PHP 8.4+
- フレームワーク: Laravel 12.x
- 認証: Laravel Sanctum（SPA認証 / セッションベース）
- DTO: Laravel Data (spatie/laravel-data)
- テスト: PHPUnit
- アーキテクチャ: 7層レイヤード

## 実装手順（Phase単位で記載）

### Phase 0: 環境準備
- Sanctum設定確認・セッションテーブル確認
- 認証関連の設定ファイル確認・調整

### Phase 1: Model層
- User Model確認（既存のfillable, casts, relations）
- 必要に応じてModel拡張

### Phase 2: Repository層
- UserRepositoryInterface定義
- UserRepository実装（findByEmail等）

### Phase 3: UseCase層
- LoginData DTO（Laravel Data）
- AuthenticatedUserData DTO
- LoginUseCase（認証、セッション再生成）
- LogoutUseCase（セッション無効化）
- GetAuthenticatedUserUseCase

### Phase 4: Controller層
- LoginRequest（FormRequest バリデーション）
- AuthController（login/logout/user エンドポイント）
- APIルート定義（routes/api.php）
- カスタムレートリミッター設定

### Phase 5: セキュリティ強化
- セッション設定強化（config/session.php）
- Sanctum設定（config/sanctum.php）
- CORS設定確認

### Phase 6: DI設定
- UserRepositoryInterface → UserRepository バインド
- ServiceProvider登録

### Phase 7: ドキュメント
- API仕様書
- セットアップガイド

## 完了条件

- [ ] ログイン・ログアウトAPIが正常動作
- [ ] PHPUnit テストがすべてパス（UseCase 80%+, Controller 70%+）
- [ ] PHPStan静的解析通過
- [ ] Laravel Pintコーディング規約通過
- [ ] Deptrac依存関係チェック通過
- [ ] セキュリティチェックリスト準拠（セッション管理、CSRF、レート制限）

## Docker環境

すべてのコマンドは `docker compose exec app` プレフィックスで実行:
- PHP/Laravel: `docker compose exec app php artisan ...`
- Composer: `docker compose exec app composer ...`
- テスト: `docker compose exec app ./vendor/bin/phpunit ...`
